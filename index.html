OpenAI, 에이전트용 저가 모델 GPT-6.1 Terra 공개
WinBuzzer (10월 27일)

10월 26일 공개된 GPT-6.1 Terra는 GPT-5.6 Terra의 후속으로, 가변 추론 노력을 지원한다. 에이전트 평가 Agents' Last Exam에서 중간 추론 노력 기준 전작보다 15%p 개선됐고, 과제 비용은 약 3분의 1 수준이라고 OpenAI는 밝혔다. Astra·Sol보다 3배 이상 빠르다는 주장도 함께 나왔다. 제공처는 ChatGPT Work와 Codex이며, 일반 ChatGPT 대화에는 들어가지 않는다. 다만 같은 보도에서 숨은 데이터 패턴 파악과 반복 회계 작업에서의 약점도 지적됐다.

경쟁축이 "가장 똑똑한 모델"에서 "작업별 최적 비용·속도"로 이동하고 있다. 고빈도 작업을 범용 플래그십으로 돌리는 시대는 끝나가고 있다. 벤더 수치는 자체 평가이므로, 자기 코드베이스의 실제 태스크로 실패율을 재보는 과정이 먼저다.

OpenAI·앤트로픽·구글 딥마인드, 사이버 안전 공동 대응
GenZ NewZ · BitRss (10월 27일) — 2차 매체 기반, 원문 확인 필요

세 연구소가 수주간 조율한 끝에 10월 27일 사이버 중심 모델·보호장치·접근 프로그램을 공동으로 공개했다고 보도됐다. 같은 주 스코틀랜드 AI 안전 서밋에는 같은 연구소 경영진과 엔비디아가 모였고, 인가된 보안 훈련에서 Claude가 OpenAI 내부 시스템 침투에 성공했다는 별도 보도도 나왔다.

치열하게 경쟁하는 3사가 특정 리스크만큼은 공동 대응에 나섰다는 것 자체가 신호다. 업계 표준이나 제품 정책이 "각사 자율"에서 "공동 최소 기준" 쪽으로 움직일 가능성을 보여준다. 단, 이 기사는 2차 매체·AI 보조 기사 기반이라 세부 내용은 원문 확인이 필요하다.

🔧 하네스 관점
에이전트에 셸·배포 권한을 줄 때 보호장치는 프롬프트 문장 하나로 맡기면 안 된다. 샌드박스·권한 범위·외부 승인 게이트에서 강제하고, 코드 리뷰에는 보안 검토를 별도 단계로 두는 구조가 필요하다. 어제 브리핑의 악성 AGENTS.md 공격과 같은 맥락이다.

오라클 클라우드에 구글 TPU 상륙… 칩·모델 유통 재편
The Diary of AI (10월 27일)

오라클과 구글은 2027년부터 구글 TPU를 오라클 클라우드 인프라(OCI)에서 제공한다고 밝혔다. 구글 밖 하이퍼스케일 클라우드에서 TPU가 제공되는 첫 사례다. 엔비디아 Vera Rubin 시스템은 즉시 이용 가능하고, OpenAI의 자체 칩 Jalapeño와 Cerebras도 라인업에 포함되며, ChatGPT와 Codex가 오라클 애플리케이션에 내장된다.

기업은 특정 클라우드·특정 칩에 묶이지 않고 약정 예산 안에서 모델과 인프라를 고를 수 있게 된다. 모델 유통 경쟁이 클라우드 3사 전체로 확산됐다는 점에서 가격·제공 조건 협상력도 달라진다. 단, Jalapeño 도입 시기는 CNBC 보도 기준 미확정이고, 실제 가격·리전·성능 수치가 나오기 전에는 아키텍처 결정을 미루는 것이 안전하다.

오픈소스 코딩 에이전트 물결: Pi 1.0과 Nanbeige4.3-33B
tech-insider · avakata.agency (10월 25~27일) — 자체 주장 기준, 확인 필요

Earendil의 Pi 1.0은 MIT 라이선스의 오픈소스 코딩 에이전트로, 15개 이상 프로바이더에 연결되며 Codemode 기능이 프롬프트 토큰을 약 40% 줄인다고 주장한다. Nanbeige4.3-33B는 Apache 2.0 오픈웨이트 코딩·에이전트 모델로, 512K 컨텍스트를 갖추고 퀵스타트는 4개 GPU 기준이며, 3B 증류 모델도 예고됐다. 두 수치 모두 자체 주장이라 독립 검증이 필요하다.

모델과 하네스가 분리되면 벤더 종속 없이 모델을 교체할 수 있고, 로컬·저가 운영이라는 선택지가 생긴다. 다만 33B급 로컬 운영은 토큰 요금을 GPU 비용으로 바꾸는 것이라 총비용 비교가 필수다.

🔧 하네스 관점
Pi 같은 멀티프로바이더 하네스에 AGENTS.md 듀얼 검수 패턴을 이식하는 발상이 유효하다. 다만 리뷰 품질은 모델 자체보다 지시문·검증 단계·증거 수집 방식이 결정하므로, 하네스를 특정 모델로부터 분리해 두는 설계가 장기적으로 유리하다. 네 codex-review-harness가 이미 그 방향에 가깝다.
