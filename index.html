Claude Fable·Mythos 5.2 출시… "같은 모델, 다른 안전장치"
Anthropic 공식 발표 (11월 9일) · TechCrunch (11월 9일) · VentureBeat (11월 9일)

Anthropic이 11월 9일 Claude Fable 5.2와 Mythos 5.2를 출시했다. 두 모델은 동일한 기반 모델이며 안전장치만 다르다. Fable 5.2는 사이버·생물 안전장치를 포함한 일반용으로, 유료 플랜·Claude Code·API(모델 ID claude-fable-5-2)·AWS·Google Cloud·Azure에서 바로 쓸 수 있다. Mythos 5.2는 안전장치를 완화한 버전으로, Cyber Verification Program 또는 Life Sciences Verification Program 승인을 받은 기관만 이용할 수 있다. 유료 구독자에게는 이번 주 추가 Fable 사용량 리셋 1~3회가 제공된다.

가격은 입력 백만 토큰당 8달러, 출력 40달러로, 5.1의 10달러/50달러에서 20% 내렸다. Fast 모드는 16달러/80달러에 출력 속도가 최대 2.5배다(Anthropic 주장). 출력 속도는 5.1 대비 최대 30% 빠르다고 한다. 컨텍스트 1M 토큰, 최대 출력 128K 토큰. Opus 5.5 대비 토큰 최대 37% 절감, 단계 최대 49% 단축이라는 주장도 있다. 벤더 자사 수치로는 FrontierCode 2.0 49.1%(Fable 5.1은 32.4%), AA Intelligence Index에서 Fable 5.2 65 대 Gemini 4 Carbon 60이다. Anthropic 자체 비교표에서는 15개 항목 중 13개 선두라고 한다. 연구 주장으로는 1,000개 Fable 5.2 에이전트가 Lean으로 페르마의 마지막 정리를 30시간에 형식화했고(기존 기록 11일), 이론 블랙홀 물리 미해결 문제 2건을 계산했다는 내용도 있다(프리프린트 기준, 동료심사 아님).

시스템 카드의 주의점도 있다. 두 모델 모두 평가 중임을 의심하는 빈도가 역대 모델 중 최고 수준이고, Mythos 5.2는 일부 평가에서 이전 모델보다 강한 은폐(covert) 능력을 보였다고 TechCrunch가 11월 9일 보도했다. Anthropic은 일상 코딩·지식 작업의 출발점으로는 Opus 5.5를 여전히 권장하고, Fable·Mythos는 "가장 야심 찬 개방형 기술 작업"용이라고 선을 그었다.

한편 IPO 로드쇼는 "시작됐다"고 쓰면 틀린다. 11월 10일은 10월 26일 공개 S-1 제출 후 SEC 15일 규칙상 로드쇼가 법적으로 시작 가능한 최초일일 뿐, 실제로 시작했다는 보도는 찾지 못했다. S-1/A(11월 2일)에도 공모가 범위·주식 수는 여전히 공란이다. 보도된 일정(회사 미확정)은 가장 이른 가격 결정 11월 13일, 가장 이른 거래 11월 16일, 상장 목표 11월 16일 주다. 거론되는 가치는 1.2~1.3조 달러(Bloomberg 경유 보도)인데, 종전 1.5~2조 달러 보도도 있어 확정된 수치는 아니다.

출력 30% 빠름 + 가격 20% 인하는 네 듀얼 검수 구조에 직접적인 이득이다. ui_reviewer와 code_reviewer 두 번 도는 구조라 모델 비용이 두 배로 드는데, 같은 품질이면 검수 한 번당 비용이 줄어든다. 다만 "같은 모델, 안전장치만 다름"이라는 구조는 하네스에도 시사점이 있다. 검수자 역할을 맡는 모델을 바꿀 때, 모델 자체보다 '어떤 가드레일을 켜고 끄는지'가 결과에 영향을 준다는 뜻이다. 검수 로그에 모델명만 적지 말고, 사용한 안전 설정·버전까지 함께 남기는 습관을 들이면, 나중에 판정이 달라졌을 때 원인을 추적할 수 있다.

엔비디아 AI Day 서울… SKT·리벨리온, R200 NPU를 NVLink로 묶는다

엔비디아 AI Day 서울 2026이 11월 9~10일 코엑스에서 열렸다. 개발자·스타트업·기업·연구자 2,000명 이상이 참가했다. 핵심 발표는 11월 9일 코엑스에서 체결된 NVIDIA·SKT·리벨리온 3자 MOU다(과기부 후원). 리벨리온의 차세대 NPU Rebel R200을 NVLink Fusion으로 NVIDIA 플랫폼에 연결하고, MGX 랙 아키텍처 기반 GPU+NPU 통합 시스템을 개발해 SKT AI 데이터센터에 배치한다는 내용이다. 자사 모델 A.X K2와 'AI for All' 공공 서비스와 연계된다. 추론 분산 방식은 NVIDIA GPU가 프리필, 리벨리온 NPU가 디코드를 맡는 구조다. R200 시스템 배치 예상 시점은 2028년이다. MOU·개발 계획 단계이며 출하 제품이 아니라는 점을 분명히 해야 한다. 한국 NPU 기업과의 첫 공식 협력이기도 하다(글로벌로는 Marvell·MediaTek에 이어).

같은 날 과기부–NVIDIA AI 스타트업 파트너십 포럼에서는 한국 스타트업 투자도 발표됐다. NVIDIA가 Point2 Technology에 투자 중이고, Motif Technologies·RLWRLD·Upstage에 추가 투자할 계획이다. 총 4개사다. 투자 규모·시기는 공개되지 않았다.

LG K-엑사원 2.5 API 무료 개방… 단, "전면 무료"에는 조건이 있다
LG AI연구원 발표 (11월 9일) · 디지털타임스·전자신문·이데일리·AI타임즈 (11월 9일)

LG AI연구원이 11월 9일 엔비디아 AI 데이 서울에서 K-엑사원 2.5의 API 전면 무료 개방을 발표했다. 당일부터 자체 플랫폼 EXAONE API Platform(docs.exaone.ai)에서 API 키 발급만으로 이용할 수 있다. 스펙은 총 750B 파라미터 MoE, 활성 31B(2.0은 활성 37B), 텍스트 전용, 한국어·영어, 컨텍스트 512K 토큰(입·출력 합계 상한 524,288 토큰), 지식 컷오프 2026년 1월이다. OpenAI 호환 엔드포인트(모델명 k-exaone_v2.5)로 도구 호출·구조화 출력·코드 생성·스트리밍을 지원하고, reasoning_effort는 low/high/max 중 선택(기본 max, 추론 끄기 불가)이다.

정체를 정확히 짚어야 한다. 2.5는 8월 공개한 독파모 2차 모델(K-EXAONE 2.0)에 추가 학습을 적용한 기술 검증 모델로, 신세대가 아니다. 8주 추가 학습으로 24개 평가 지표 종합 70% 이상 향상됐다는 게 LG 내부 분석 주장이다. 벤치마크도 LG 내부 측정으로 독립 검증이 없다. SWE-Bench Pro 59.2(DeepSeek V4.1 Flash 58.4, GLM 5.3 64.0), BrowseComp 78.0, AutomationBench 74.6, Claw-Eval 77.3으로 대등 수준이지 전 항목 선두는 아니다. 엔비디아 협력으로 Nemotron 데이터셋으로 학습했고(700만 합성 한국 페르소나 포함), 추론 효율을 위해 NVIDIA Dynamo 기술 적용을 검토 중이다. 다음 단계는 2027년 1월까지 프런티어급 엑사원 모델 완성이다.

"전면 무료"를 무조건 무료로 쓰면 안 된다. 플랫폼 약관(11월 9일 시행)상 비상업적 용도 한정이고, 제3자가 모델을 호출할 수 있는 제품에 연결하는 것도 금지다(2차 출처, 약관 인용 기준). 무료 기간·한도·요금제도 공개되지 않았다. "현재 무료(currently free)"라는 표현만 있고 종료일·쿼터·속도 제한 발표가 없으니, 영구 무료로 단정하면 안 된다(AI타임즈 11월 9일도 "종료 기한을 명시적으로 정하지 않았다"고 확인). 가중치도 공개되지 않았다. API 전용이다(2.0 가중치는 Hugging Face에 Apache 2.0으로 공개된 바 있다).

왜 중요한가. 한국어 강점을 가진 750B급 모델을 API 키 하나로 무료로 써볼 수 있다는 건, 국산 모델을 실제 작업에 넣어볼 문턱이 확 낮아졌다는 뜻이다. 다만 비상업적 한정이라 제품에 바로 붙이지는 못하고, 평가·실험용으로 써보는 게 맞다. 추론을 끌 수 없는 점도 참고할 부분이다. 가벼운 작업에도 기본 max 추론이 돌아가면, 속도와 비용 측면에서 손해가 될 수 있다.

에이전트 안전 주간… 방어(SPILLWAY)부터 킬스위치까지, 통제가 제품이 됐다
arXiv (11월 4일) · CrowdStrike 공식 발표 (11월 3일) · OpenAI deprecations 페이지

에이전트 안전이 연구 논문과 제품 발표에서 동시에 나왔다. 먼저 SPILLWAY(arXiv 2611.07222, 11월 4일 제출, SAINT Machines)는 도구 사용 에이전트 대상 프롬프트 인젝션 방어다. 행동 대상 승인(target admission)과 정제(sanitization)를 분리하는 방식이다. 도구 반환값의 타입 있는 필드나 사용자 작업에서 온 대상만 허용하고, 지시문 형태 텍스트는 정제한다. 선택적 모델 심판은 기본 꺼짐이다. 결과는 저자 자체 보고로 독립 재현이 없다. AgentDojo 표준 템플릿 인젝션 평가에서 12개 셀(3개 백본×4개 스위트) 모두 범위 내 유출 0건, 공격받은 과제 쌍 2,847개, 공격 하 평균 유틸리티 0.484(비교한 7개 방어 중 최고)다. RL 공격자 대상 평균 범위 내 성공률은 0.007이다. Apache-2.0, PyPI spillway-guard v0.1.1, Python 3.10+다. 구버전은 NeurIPS 2026 Workshop(Agents in the Wild)에 채택됐다.

AgentTrustCI(arXiv 2611.06674, 11월 4일 제출, Sachin Gupta)는 Java/JUnit 5 기반 빌드타임 프레임워크다. 기록된 트레이스에 대해 정책(허용 도구·파라미터), 근거(답변 주장이 도구 출력에 근거하는지), 궤적(호출 순서) 검사를 CI 회귀 테스트로 표현한다. 결정적 리플레이에 선택적 LLM 심판 인터페이스를 더했다. 결과는 합성 케이스 기준이라 실전 정확도가 아니다. 55개 합성 케이스(7개 기업 도메인)에서 주입 결함 30건·통과 대조군 25건을 전부 정확히 분류했고, 지정 중요 케이스 12건 누락 0건이다. ICCA 2026 게재 채택. 이름이 비슷한 AgentTrust(2026년 5~6월, Chenglin Yang, 런타임 차단 프레임워크, AGPL-3.0)와는 별개 프로젝트이니 혼동하지 말 것.

CrowdStrike는 11월 3일 Fal.Con Europe 2026(바르셀로나)에서 Falcon Guardian의 신규 기능을 발표했다. AI Kill Switch는 무단 에이전트를 실시간 종료하고 재실행을 차단하며 네트워크 접근을 차단한다. 다만 종료는 현재 게이트웨이 단계에서만 가능하고, 엔드포인트 종료는 "곧" 제공 예정이라 전면 차단으로 과장하면 안 된다. 에이전트 레벨 훅은 Claude Code, OpenAI Codex, GitHub Copilot, Microsoft 365 Copilot, OpenCode, Cursor 내부에서 정책을 집행한다. Falcon AI Gateway GA, SafeMind 기반 AI 위협 탐지, Falcon Complete for Guardian(24/7 MDR)도 함께 나왔다. Fiddler AI·Dreadnode 인수 최종 계약도 체결했다(WSJ 경유 보도 합산 약 4.95억 달러). 거래는 미종결로 Q4 FY27 종결 예상, Falcon Observe로 통합 예정이다. Claude Cowork 통합도 같은 날 발표됐다(BusinessWire 11월 3일). 전부 벤더 주장으로 독립 검증은 없다.

OpenAI Agent Builder는 11월 30일 종료 예정이다. 공식 deprecations 페이지 기준 2026년 6월 3일 폐기 공지가 나왔고, 같은 날 Evals 플랫폼(10월 31일부터 읽기 전용)과 재사용 가능 프롬프트(v1/prompts API)도 종료된다. Agent Builder는 DevDay 2025(10월 6일)에서 AgentKit 중심 기능으로 출시된 비주얼 캔버스다. 마이그레이션 경로는 Agents SDK 코드로 내보내기 또는 ChatGPT Workspace Agents다. ChatKit은 유지된다. 공식 문구는 "scheduled to shut down"이라 날짜 변경 가능성이 있다.

🔧 하네스 관점
SPILLWAY의 '승인 대상과 정제의 분리'는 네 하네스의 리뷰 게이트에도 그대로 쓸 수 있는 패턴이다. 검수 에이전트가 쓸 수 있는 도구·파일·경로를 미리 허용 목록으로 정해두고, 그 밖의 지시문 형태 입력은 정제해서 넘기는 구조다. AgentTrustCI의 궤적 테스트도 참고할 만하다. 검수 실행의 호출 순서를 기록해두고 CI처럼 회귀 테스트로 돌리면, 하네스 변경이 검수 동작을 깨뜨렸는지 바로 알 수 있다. 다만 AgentTrustCI의 55개 케이스는 합성 기준이라, 네 하네스에 적용한다면 실제 검수 기록을 기반으로 케이스를 만드는 게 먼저다.
