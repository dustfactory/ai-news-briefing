Anthropic, 에이전트 메모리 'dreaming' 설계 공개… 세션 사이 오프라인 정리
Anthropic 엔지니어링 블로그 "The components of agent memory" (11월 6일)

Anthropic이 11월 6일 에이전트 메모리의 구조를 다룬 연구 글을 냈다. 핵심은 dreaming이다. 세션이 끝난 뒤 Claude가 자신의 로그와 트랜스크립트를 다시 읽어 메모리의 오류를 고치고, 링크드 위키를 만들고, 다음 세션에 무엇을 로드할지 정하는 오프라인 정리 패스다. 가중치는 건드리지 않고, 메모리는 파일(컨텍스트) 형태로 유지된다. 메모리는 네 층으로 나뉜다. 검색 가능한 이벤트 로그(트랜스크립트) → 메모리 노트 → 표현(위키 등) → 매 세션 주입되는 컨텍스트. dreaming은 이 층들 사이에서 동작한다.

수치는 전부 Anthropic 자체 평가로, 독립 검증은 없다. CL-Bench 1.0 데이터베이스 태스크에서 메모리를 쓰자 Opus 5.5가 0.655에서 0.838로, Sonnet 5.5가 0.644에서 0.833으로 올랐다. 위키 실험(내부 문서 약 35만 개, 약 4억 2천만 토큰, 25개 질문)에서는 위키만으로 dreaming 2회 13%에서 128회 48%로 올랐다. 검색만 썼을 때 53%, 위키+검색은 54%에서 61%였다. 포켓몬 레드 사례도 있다. 잘못된 포켓센터 위치 노트가 루프를 만들자 dreaming이 트랜스크립트와 대조해 노트를 수정했다.

제품 상태는 정확히 짚어야 한다. dreaming 자체는 5월 6일 Code w/ Claude에서 발표된 Claude Managed Agents의 연구 프리뷰 기능(Dreams API)이다. 이번 11월 6일 글은 제품 출시가 아니라 설계와 평가를 다룬 글이다. Dreams API는 기존 메모리 스토어와 최대 100개 이전 세션을 받아 새 스토어를 반환하는 copy-on-write 방식이다. 입력은 건드리지 않고, 수분에서 수십 분이 걸리며, 일반 API 토큰 요금이 적용된다. 프리뷰 지원 모델은 Opus 4.7과 Sonnet 4.6이다. 주의할 점도 있다. 25개 질문 같은 소규모 평가셋에 일부 단일 실행이고, "실패만 기록" 규칙은 오히려 이득을 깎았다(Opus 5에서 −0.234). Claude Code의 자동 메모리는 MEMORY.md의 처음 200줄 또는 25KB만 로드한다. 정리 주기는 미정이다. 계산 비용이 드는 오프라인 작업이라는 점이 열린 문제다.

왜 중요한가. 에이전트가 길게 일할수록 "기억"이 아니라 "기억의 정리"가 병목이 된다. 컨텍스트를 무한히 늘리는 대신, 세션 사이에 무엇을 버리고 무엇을 다듬을지를 정하는 층이 생겼다는 것이 본질이다. 메모리를 가중치가 아니라 파일로 두는 선택은, 기억을 사람이 읽고 고칠 수 있게 남겨둔다는 뜻이기도 하다.

🔧 하네스 관점
dreaming은 네 검수 하네스의 "리뷰어가 트랜스크립트를 다시 읽고 기록을 고친다"는 패턴과 같은 구조다. 메모리를 파일로 두는 것은 AGENTS.md·MEMORY.md 패턴과 같고, Dreams API의 copy-on-write는 "진실의 원본을 그 자리에서 고치지 않는다"는 규칙과 같다. 교훈 하나는 "실패만 기록" 규칙이 오히려 성능을 깎았다는 점이다. 리뷰 기록에 성공 사례도 함께 남기지 않으면, 기록이 현실을 왜곡한다는 뜻이다. 네 하네스의 리뷰 기록 형식을 점검할 때 참고할 만하다.

Cursor 변경 로그 · Codex GitHub 릴리스 · Anthropic 변경 로그 (11월 6일)

11월 6일 하루에 코딩 도구 세 곳이 나란히 업데이트를 냈다. Cursor는 에이전트와 실시간 양방향 음성 통화를 추가했다. 음성 에이전트가 대화를 맡고 코딩 에이전트는 계속 작업한다. 말하면서 진행 상황을 묻고 diff와 실행 상태를 조회할 수 있다. Agents Window·IDE·웹·iOS에서 동작하고, iOS는 "Hey Siri, call Cursor"으로 시작한다. 음성은 Grok Voice 기반(목소리 Ara·Eve·Leo·Rex·Sal)이고, 코딩 모델은 선택한 모델 그대로다. 기존 받아쓰기(Voice Mode)와는 별개 기능이다. 로그인 계정이 필수이고 API 키 인증 세션에서는 시작할 수 없으며, 일일 통화 한도가 있다(수치 미공개). 약 10분 무음 시 자동 종료되고, Privacy Mode에서는 zero data retention이다. 가격 변동 발표는 없다.

Codex CLI 0.167.0은 실제 존재하는 버전이다. GitHub 릴리스 rust-v0.167.0이 11월 6일 01:40 UTC에 게시됐고 변경은 136건이다. 헤드라인은 에이전트 커맨드 센터를 codex agents --no-daemon으로 여는 것이다. 커맨드 센터와 세션 피커에 읽지 않은 결과 표시가 들어갔다. 그 외에 터미널 세션 피커에서 백엔드 전환 시 초안 유지, 작성 중 로컬 이미지 첨부 미리보기, 트랜스크립트의 클릭 가능한 경로로 본 이미지 열기, Vertex AI 설정용 gcp_setup_wizard 플래그, macOS·Windows 시스템 프록시 옵트인, 승인 프롬프트 열린 상태에서 패치 상세 펼치기 등이 있다. 모델 변경은 없고, 멀티 에이전트 관리(감독) 개선 릴리스다.

Claude Code 2.1.319의 헤드라인은 MCP 태스크 백그라운드 실행이다. MCP 서버가 도구 호출을 태스크로 실행하면 Claude Code가 즉시 백그라운드로 보내고, 끝나면 결과를 보고한다. 해제용 환경변수는 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND다. 신규 설정 permissions.denyInsteadOfPrompting은 권한 프롬프트에서 멈출 도구 호출을 거부하고 턴을 계속 진행하게 한다. 터미널·서브에이전트·팀메이트 환경에서 무인 실행에 직접 닿는다. Auto mode도 바뀌었다. LLM 게이트웨이 뒤에서 텔레메트리·피처 플래그가 꺼져 있으면 서버가 검사하지 못하는 호출은 묻거나 거부하고, 내장 분류기로 폴백하지 않는다. CLAUDE_CODE_AUTO_MODE_SERVER=0으로 기존 동작을 유지할 수 있다. 그 외에 워크트리 생성 중 샌드박스 탈출을 포함한 권한 우회 수정 여러 건과 오래된 핸드셰이크 MCP 서버 연결 실패 수정이 있다.

한국 VIDRAFT Darwin-180B, 수학·과학 추론 73.68… 오픈웨이트 1위, 다만 '하위 점수'다
SuperCLUE 2026년 11월 리더보드 (11월 5일) · VIDRAFT 발표 (11월 6일)

한국 VIDRAFT의 Darwin-180B-RSI-R3이 SuperCLUE 11월 리더보드에서 수학·과학 추론 하위 카테고리 73.68점을 받았다. 19개 모델 중 전체 2위이고, 오픈웨이트 중에서는 1위다. 1위는 GPT-6.1-Sol의 76.32점이다. 비교하면 Gemini 4-Argon 71.05, DeepSeek V4.1-Flash 71.05, Grok 4.7 68.42다. 다만 73.68은 전체 순위가 아니라 한 카테고리 점수다. 종합 점수는 43.08점으로 19개 중 9위, 오픈웨이트 중 5위다. 보드에서 유일한 한국 모델이다.

모델은 180B MoE이고 추론 시에는 약 3B 파라미터만 활성화된다. 부모 모델은 Qwen3.8-Flash-Next 기반이다. RSI는 Recursive Self-Improvement의 약자로, 검증된 정답에 대해서만 재학습하는 자기개선 루프다. 파라미터의 약 0.02%만 변경했다고 주장한다. Qwen 커뮤니티 라이선스 1.0으로 상업 이용이 가능하고, 가중치는 HF FINAL-Bench/Darwin-180B-RSI에 공개됐다.

주의할 점이 있다. SuperCLUE는 중국의 벤치마크(CLUE 계승)다. 중국 외 모델은 참고용으로 등재되고 공식 순위는 별도로 표기된다. "한국 모델 세계 2위"로 읽으면 틀린다. 하위 카테고리 2위, 종합 9위가 정확한 표현이다. GPQA Diamond 94.44(1위) 주장은 2차 보도 기준이라 벤더 주장으로 다뤄야 한다. POCKET-Darwin-180B 4비트(111GB)가 8GB VRAM·32GB RAM 노트북에서 4.17 tok/s로 돌아간다는 주장과, POCKET 패밀리 11월 1일 기준 누적 315만 다운로드도 VIDRAFT 측 주장이다.

왜 중요한가. 한국 팀이 만든 오픈웨이트 모델이 프론티어급과 같은 표에 오른 것 자체가 의미 있다. 다만 평가의 무게중심은 "어디서 2위인가"에 있다. 수학·과학 추론이라는 한 축에서 강하다는 것이지, 범용 순위 2위가 아니다. 부모 모델이 Qwen3.8-Flash-Next라는 점도 눈에 띈다. 네가 로컬(Strata)로 돌리는 모델과 같은 계열이라, 이 모델의 추론 방식이 로컬 환경에서 어떻게 굴러가는지 가늠할 실마리가 된다.
