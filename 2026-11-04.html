OpenAI 'Pando'… Git을 버리지 않고 받아내다
OpenAI 엔지니어링 포스트 (11월 2일) · Interesting Engineering

OpenAI가 모노레포용 Git 백엔드 Pando를 공개했다. 계기는 Codex다. 마스터 커밋이 2024년 1분기 대비 2026년 3분기 1,378% 증가했고, 4분기 추정치는 2,442%에 달한다. 한 엔지니어가 여러 변경을 동시에 굴리고 각 푸시가 CI 체크아웃을 대량으로 유발하면서, 기존 시스템은 한때 머지 신뢰도가 90% 아래로 떨어지기도 했다. Pando는 2026년 4월부터 프로덕션에서 돌고 있고, Rust로 10주 만에 만들었으며 핵심 설계는 엔지니어 1명, 구현은 에이전트 팀이 맡았다고 한다.

설계의 요지는 Git 클라이언트와 워크플로는 그대로 두고 서버 뒤쪽만 갈아엎은 것이다. 저장소 전체 순서를 강제하지 않고 브랜치별 인과 일관성으로 병렬 처리하고, 동일 ref에 대한 푸시만 원자적 비교·교환으로 직렬화한다. 팩파일 재사용과 LSM식 백그라운드 컴팩션으로 읽기 부하를 줄이고, 캐시 적중률은 99%를 넘는다고 한다. 결과 수치(자사 발표): 푸시 중앙값 지연 약 80% 감소, 머지 신뢰도 99.99%, 하루 약 1PB의 Git 데이터 서빙, 한 시간에 57TB 이상 처리. 흥미로운 대조는 Anthropic이 10월에 Git 자체를 버리고 Scion으로 교체한 반면, OpenAI는 Git을 유지하고 백엔드만 교체했다는 점이다. 같은 강제 요인에 대한 정반대 해법이다.

🔧 하네스 관점
듀얼 검수처럼 리뷰 에이전트를 병렬로 늘리는 구조는 검수 품질 이전에 Git·CI 경합을 먼저 키운다. 하네스 설계에 "검수 에이전트는 읽기 전용으로 돌리고, 쓰기는 한 경로로 모은다"는 원칙을 AGENTS.md에 명문화해 두면 Pando가 해결하려 한 문제의 소규모 버전을 사전에 피할 수 있다.

볼 포인트 ─ OpenAI의 업스트림 Git 기여가 일반 호스팅에 스며드는지, Scion과의 장기 운영 비용 비교 공개 여부. 자사 수치라 독립 검증은 아직 없다.

DeepSeek 슈퍼에이전트… 요청을 먼저 발견한다
DeepSeek Harness 팀 (10월 31일) · MIT Sloan India

어제 다룬 슈퍼에이전트의 후속 정보다. 구조는 2층이다. Router가 들어오는 요청을 평가해 작업으로 승인할지 가리고, Worker가 별도 코딩 세션에서 실행해 PR 같은 결과물로 되돌려준다. 감시 대상은 GitHub 저장소 활동이고, 선택적으로 직장 메신저 Feishu 대화도 본다. 승인된 요청만 추적 가능한 작업으로 전환한다는 점이 포인트다. 경쟁 축이 '더 잘 코딩하기'에서 '요청을 먼저 발견하고 끝까지 챙기기'로 이동하고 있다는 신호다.

다만 DeepSeek 스스로 "상용 제품이 아니라 연구용"이라 못 박았고, 공개 코드가 내부 구현과 다르며 일부 기능은 아직 개발 중이라고 밝혔다. 당장 프로덕션에 올릴 물건은 아니지만, '요청 접수 → 승인 → 작업 추적 → 결과 회신' 파이프라인 자체는 팀의 이슈 트리아지나 dependabot류 자동화에 바로 응용할 수 있는 형태다. 특히 승인 게이트를 에이전트 앞단이 아니라 Router 계층에 둔 설계는, 무분별한 자동 실행을 막으면서도 상주성은 유지하는 절충안으로 참고할 만하다.

🔧 하네스 관점
네 하네스는 사람이 Codex를 호출하면 AGENTS.md 지시문과 듀얼 검수가 동작하는 '호출형'이다. 슈퍼에이전트는 그 앞에 '무엇을 할지 고르는 Router'를 하나 더 얹은 형태라, 하네스를 상주형으로 확장한다면 Router 역할을 AGENTS.md에 "승인 기준 + 작업 단위 정의"로 명문화하는 것이 가장 자연스러운 접목점이다. 단, Router의 오판이 곧 잘못된 작업 실행으로 이어지므로 승인 로그와 되돌리기 경로를 검수 결과와 같은 수준으로 남기는 것이 전제다.

볼 포인트 ─ 실제 GitHub 이슈 처리 성공률과 PR 머지율 같은 실측 평가, Feishu 외 Slack·Jira 연동 속도.

ElevenLabs 'Eleven Realtime'… 음성 조립을 하나로
ElevenLabs (11월 3일) · 디지털데일리 · 파이낸셜뉴스

음성 에이전트를 만들려면 음성인식, 발화 구간 감지, 턴테이킹, LLM, 음성합성을 각각 골라 이어 붙여야 했다. ElevenLabs는 11월 3일 이 전부를 하나의 음성-대-음성 모델로 묶은 'Eleven Realtime'을 공개했다. 두 가지 버전이다. v1 Mini는 빠르고 자연스러운 대화용(AI 비서, 교육 튜터, 게임 캐릭터), v1 Max는 정해진 절차에 따라 정보를 조회하고 도구를 호출하는 다단계 작업용(고객 지원, 리드 선별)이다. 끼어들기 대응, 도구 호출, 자연스러운 턴 전환을 공통 지원하고, 한국어·일본어 포함 90개 이상 언어, 1만 7,000개 이상 보이스 라이브러리를 지원한다.

제3자 평가기관 Artificial Analysis(10월 기준)에 따르면 Max는 Big Bench Audio에서 98.8% 정확도, 질문 종료 후 답변 시작까지 0.57초, Full Duplex Bench는 Mini 95.8%·Max 94.1%였다. 제공 경로는 Eleven Agents 플랫폼과 OpenAI Realtime API 호환 WebSocket API이며, 출시 시점에는 WebRTC를 지원하지 않는다. 음성 에이전트의 진입 장벽이 '파이프라인 설계 능력'에서 '모델 선택과 프롬프트·도구 설계'로 이동했다는 점이 핵심이다. 다만 가격 정보는 이번 발표에서 확인되지 않았으니(확인 필요), 상용 투입 전 분당·호출당 단가를 따로 확인해야 한다.

오늘 베타 시작… 중국판 애플 인텔리전스
Apple · Alibaba (10월 31일) · 연합뉴스 · 나우뉴스

어제 다룬 중국판 애플 인텔리전스의 베타가 오늘(11월 4일) 시작된다. 12월 iOS 27.3 정식 출시와 함께 중국 사용자에게 제공된다. Siri, 글쓰기 도구, 시각 지능 등에서 알리바바 Qwen이 텍스트·이미지 이해와 생성을 일부 지원하고, 애플 자체 파운데이션 모델이 핵심 경험을 맡고 Qwen은 클라우드 기반 일부 기능을 보완하는 구조다. 기능별 라우팅 세부 사항은 공개되지 않았다. 대상은 중국에서 애플 인텔리전스 지원 아이폰을 구매하고 기기 위치와 계정 국가가 모두 중국인 사용자로 한정되며, 아이폰 15 프로 이후 모델이 해당한다.

WWDC 2026에서 공개된 차세대 Siri AI와 화면 인식·크로스앱 에이전트 기능은 이번 중국판에 포함되지 않는다. 중국 국가인터넷정보판공실(CAC)은 올해 7월 애플 인텔리전스를 신규 승인 사업자 명단에 올렸고, 연합뉴스 보도에 따르면 사용자의 질문·답변은 알리바바 모델 훈련에 쓰지 않는다고 한다. 글로벌 AI 제품이 지역 규제에 맞춰 파운데이션 모델 자체를 갈아끼우는 선례가 본격화된 것이다. 중국 외 지역은 ChatGPT, 중국은 Qwen이라는 이중 구조는, AI 기능의 국가별 분기·라우팅·프라이버시 경계 설계가 제품 아키텍처의 일급 관심사가 된다는 뜻이다. Anthropic이 Qwen 측의 대규모 증류 시도를 주장한 바 있다는 나우뉴스 보도도 함께 따라다닌다.

볼 포인트 ─ 오늘 시작되는 개발자 베타 피드백에서 실제 라우팅 범위와 품질이 얼마나 드러나는지, 아이패드·맥 지원 추가 승인 시기, 차세대 Siri의 중국판 합류 시점.
